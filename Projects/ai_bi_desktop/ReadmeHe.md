### 2. **תהליך האופטימיזציה באמצעות Optuna**

לכל מודל, המערכת מבצעת את השלבים הבאים:

#### **שלב א': הגדרת מרחב החיפוש**

לכל מודל יש היפרפרמטרים ספציפיים שנבדקים. לדוגמה:

**Random Forest:**
```python
- n_estimators: 50-200 (מספר עצים)
- max_depth: 6-15 (עומק מקסימלי)
- min_samples_split: 2-5 (מינימום דגימות לפיצול)
- min_samples_leaf: 1-3 (מינימום דגימות בעלה)
```

**XGBoost:**
```python
- n_estimators: 50-200
- max_depth: 6-15
- learning_rate: 0.01-0.3 (קצב למידה)
- subsample: 0.6-0.9 (אחוז דגימות לכל עץ)
- colsample_bytree: 0.6-1.0 (אחוז פיצ'רים לכל עץ)
```

**CatBoost:**
```python
- iterations: 50-200
- depth: 5-15
- learning_rate: 0.01-0.3
- l2_leaf_reg: 1-10 (רגולריזציה)
```

#### **שלב ב': פונקציית המטרה (Objective Function)**

עבור כל ניסיון (trial) ב-Optuna:

1. **הצעת פרמטרים** - Optuna מציע סט פרמטרים חדש
2. **יצירת Pipeline** - בונים pipeline עם:
   - טיפול בנתונים חסרים (Imputation)
   - סקיילינג של נתונים (RobustScaler)
   - קידוד פיצ'רים קטגוריאליים (TargetEncoder/OneHotEncoder)
3. **Cross-Validation** - בדיקה עם K-Fold או StratifiedKFold
4. **חישוב ציון** - החזרת הציון הממוצע

```python
def objective(trial):
    params = suggest_hyperparameters(trial)
    model = create_model(params)
    pipeline = create_pipeline(model)
    scores = cross_val_score(pipeline, X, y, cv=cv)
    return scores.mean()
```

#### **שלב ג': אופטימיזציה עם TPE Sampler**

- **אלגוריתם**: Tree-structured Parzen Estimator (TPE)
- **מספר ניסויות**: מוגדר בקונפיגורציה (בדרך כלל 20-50)
- **כיוון**: מקסימיזציה של הציון
- **Timeout**: הגבלת זמן לכל מודל

```python
study = optuna.create_study(
    direction='maximize',
    sampler=TPESampler(seed=42)
)
study.optimize(objective, n_trials=20)
```

#### **שלב ד': אימון המודל הסופי**

לאחר מציאת הפרמטרים הטובים ביותר:

1. יצירת מודל עם הפרמטרים האופטימליים
2. אימון על כל סט האימון
3. חישוב מטריקות מפורטות

### 4. **הסבר על מטריקות ה-Cross-Validation**

#### **מה זה Cross-Validation?**

Cross-Validation מחלק את הנתונים ל-K חלקים (folds), ובודק את המודל K פעמים:

```
Fold 1: [Train Train Train Train | Test]
Fold 2: [Train Train Train Test | Train]
Fold 3: [Train Train Test Train | Train]
Fold 4: [Train Test Train Train | Train]
Fold 5: [Test Train Train Train | Train]
```

#### **למה זה חשוב?**

1. **מונע Overfitting** - המודל לא רואה את אותם נתונים באימון ובבדיקה
2. **אומדן אמין** - ממוצע של מספר בדיקות יותר אמין מבדיקה אחת
3. **יציבות** - סטיית התקן נמוכה = מודל יציב

#### **פרשנות הציונים:**

```
Model: 0.8891±0.0198
       ↑       ↑
   ממוצע   סטיית תקן
```

- **ממוצע גבוה** = ביצועים טובים
- **סטיית תקן נמוכה** = יציבות גבוהה
- **Gap גדול מהמודל השני** = עליונות ברורה

### 7. **Confusion Matrix (מטריצת בלבול) - סיווג**

**מתי:** עבור בעיות סיווג בלבד.

**מה היא מראה:**

```
                 Predicted
              No      Yes
Actual  No   [TN]    [FP]
        Yes  [FN]    [TP]
```

- **TN (True Negative)** - ניבאנו "לא" והמציאות "לא" ✓
- **TP (True Positive)** - ניבאנו "כן" והמציאות "כן" ✓
- **FP (False Positive)** - ניבאנו "כן" אבל המציאות "לא" ✗ (Type I Error)
- **FN (False Negative)** - ניבאנו "לא" אבל המציאות "כן" ✗ (Type II Error)

**מטריקות נגזרות:**

```
Accuracy = (TP + TN) / (TP + TN + FP + FN)
Precision = TP / (TP + FP)  -- מכל מה שניבאנו "כן", כמה באמת "כן"
Recall = TP / (TP + FN)     -- מכל ה"כן" האמיתיים, כמה תפסנו
F1 = 2 × (Precision × Recall) / (Precision + Recall)
```

**דוגמה:**
```
              Predicted Default
              No      Yes
Actual  No   [850]    [50]   ← 50 FP - ניבאנו ברירת מחדל בטעות
        Yes  [30]    [70]    ← 30 FN - פספסנו ברירת מחדל

Precision = 70/(70+50) = 0.58 (58% מהתחזיות "ברירת מחדל" נכונות)
Recall = 70/(70+30) = 0.70 (תפסנו 70% מברירות המחדל)
```

## סיכום תהליך בחירת המודל

### תהליך שלב אחר שלב:

1. **הכנת נתונים:**
   - הפרדת פיצ'רים (X) ומשתנה יעד (y)
   - קידוד משתנה יעד אם סיווג (LabelEncoder)
   - זיהוי פיצ'רים קטגוריאליים

2. **אופטימיזציה עבור כל מודל (Optuna):**
   - יצירת Optuna Study
   - הרצת 20-50 ניסויות (trials)
   - כל ניסיון מציע פרמטרים שונים
   - TPE Sampler לומד מניסויות קודמים ומשפר
   - שמירת הפרמטרים הטובים ביותר

3. **Cross-Validation:**
   - חלוקה ל-5 folds (StratifiedKFold לסיווג, KFold לרגרסיה)
   - אימון על 4 folds, בדיקה על ה-5
   - חזרה 5 פעמים עד שכל fold היה פעם אחת test
   - חישוב ממוצע וסטיית תקן

4. **בחירת המודל הטוב ביותר:**
   - מיון כל המודלים לפי ציון CV ממוצע
   - המודל עם הציון הגבוה ביותר נבחר
   - אימון סופי על כל הנתונים
   - חישוב מטריקות נוספות (Precision, Recall, F1, וכו')

5. **הסבר ונימוקים:**
   - המערכת מייצרת הסבר למה המודל נבחר
   - השוואה למודל השני הכי טוב
   - תיאור היתרונות של סוג המודל

## שאלות נפוצות

### **1. למה בוחרים ROC-AUC ולא Accuracy?**

בעיות רבות סובלות מחוסר איזון במחלקות. לדוגמה:
- 95% מהלקוחות לא נכשלים בהלוואה
- 5% כן נכשלים

מודל טיפש שתמיד מנבא "לא נכשל" יקבל Accuracy = 95%, אבל הוא חסר תועלת!

ROC-AUC לוקח בחשבון את היכולת להבדיל בין המחלקות בכל רמות ה-threshold, לא רק ב-0.5.

---

### **2. למה משתמשים ב-Cross-Validation ולא בפיצול רגיל Train/Test?**

Cross-Validation:
- ✅ משתמש בכל הנתונים גם לאימון וגם לבדיקה
- ✅ נותן אומדן יציב יותר (5 בדיקות במקום 1)
- ✅ מגלה overfitting טוב יותר
- ✅ מראה סטיית תקן = יציבות

Train/Test רגיל:
- ❌ מבזבז נתונים (20% לא משמשים לאימון)
- ❌ תלוי ב"מזל" - אם ה-test set קשה/קל במיוחד
- ❌ לא נותן מושג על יציבות

---

### **3. איך Optuna יודע אילו פרמטרים לנסות?**

Optuna משתמש באלגוריתם **TPE (Tree-structured Parzen Estimator)**:

1. **ניסויות ראשונים:** אקראי לחלוטין
2. **למידה:** לומד אילו פרמטרים נתנו ציונים טובים
3. **התמקדות:** מנסה פרמטרים דומים לטובים
4. **איזון:** ממשיך לחקור גם אזורים חדשים (Exploration vs Exploitation)

זה הרבה יותר חכם מ-Grid Search שבודק את **כל** הקומבינציות בצורה עיוורת.

---

### **4. מה זה Feature Importance ולמה זה חשוב?**

Feature Importance מראה לנו **איזה פיצ'רים באמת משפיעים** על התחזית.

שימושים:
- **פשט את המודל** - תסיר פיצ'רים לא חשובים
- **הבן את הבעיה** - מה באמת חשוב בעולם האמיתי?
- **שפר את איסוף הנתונים** - התמקד בפיצ'רים החשובים
- **הסבר החלטות** - למה המודל חזה כך?
